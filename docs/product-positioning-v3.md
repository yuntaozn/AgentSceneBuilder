# AgentSceneBuilder 正式产品定位 V3

> 状态：当前产品定位基线。V2 及更早文档仅保留为演化记录。

## 一句话定位

AgentSceneBuilder 是面向 AI 大模型的开源数字建模基础设施。大模型由宿主组织为 Agent，通过 Skill 和 CLI 检索模型、构建参数化几何、计算空间关系，并用结构化诊断验证和修正结果。

## 核心问题

Agent 即使没有本项目，也能临时编写 Three.js 或其他三维代码，但它会在每个任务中重复处理：

- 尺寸、坐标和变换；
- 基础几何和参数校验；
- 路径、阵列、网格和空间分布；
- 构件连接、间隙、方向和约束；
- 稳定命名、语义查询和工程量计算；
- 不同渲染器或模型格式之间的数据重建。

内核把这些重复的底层计算封装为可验证、可直接调用的能力。宿主 Agent 负责理解用户目标、选择方案并判断结果是否满足任务。

## 核心抽象

```text
基础几何策略
  + 参数化构件
  + CompositionSpec
  + Spatial Methods
  + Anchor / Attachment / Constraint
  = Renderer-neutral Digital Model
```

专业对象优先由通用构件、空间方法和参数组合生成。模型库先沉淀可独立复用的构件和单体设备，再用场景案例验证组合能力。

## 产品优先级

1. 空间方法：路径、重复、分布、连接、避让、约束和测量。
2. 组合协议：稳定身份、参数、语义、anchor、attachment 和生成意图。
3. 基础通用构件：体、杆、管、板、面、轮廓与路径体。
4. 可计算结果：尺寸、数量、面积、体积、长度和空间关系。
5. 方法返回契约：facts、candidates、proposal、generated composition。
6. 适配器：Three.js、Web、CAD、BIM 及模型文件。
7. 经真实任务验证后再沉淀专业复合构件。

## 不属于核心的内容

- 固定课件步骤或页面布局；
- Three.js 专用场景代码；
- 把 GLB/GLTF 当作唯一建模来源；
- 完整 BIM、CAD 或 DCC 软件替代品；
- 由内核替 Agent 选择没有唯一答案的空间方案；
- 以视觉截图作为所有任务的强制证据。

## Agent 接入形态

项目本身可以作为 Skill 安装。Skill 负责使用说明，CLI 提供本地确定性计算；宿主插件只负责安装、发现和权限边界。当前不走 MCP 或长驻本地服务路线，避免把数字建模内核过早服务化。

```text
轻量接入：Skill + CLI
插件接入：Plugin + Skill + CLI
应用嵌入：直接依赖 @agentscene/core
```

## 可视化复核

网页模型库和编辑器用于预览、验收和调参。编辑器与 CLI 共享 CompositionSpec 和 Core，调整后的模型可以回到 Agent 的检查与构建流程。

Editor 应保持静态 Web 可部署，不绑定 Node.js、特定桌面框架或专用服务。Node 启动器只是开发便利工具；用户可以选择任意能提供标准 HTTP 静态文件的环境。

## 设计判据

一项能力适合进入内核，需要至少满足多数条件：

- 多个领域都会重复使用；
- 计算实现不简单，Agent 容易重复犯错；
- 输入输出可以结构化；
- 结果可以确定性验证；
- 返回值能归入 facts、candidates、proposal 或 generated composition；
- 不替代必要的领域决策；
- 与某一渲染器或文件格式解耦。

构件数量不是成熟度指标。Agent 完成一个新任务需要自行补写多少底层空间代码，才是更重要的指标。
