# 开源数字模型库实施方案

## 定位

AgentSceneBuilder 的模型库为 AI 大模型提供可检索、可计算和可组合的参数化构件、空间建模方法和完整模型。Agent 可根据语义、能力和锚点挑选条目，读取生成索引中的 `agent` 使用说明后进行复用和检查。

Git 仓库保存清单，开放协议定义模型结构，测试验证可复用性。浏览器提供同一批条目的预览与复核。

## 内容分层

- `component`：具备参数、语义、锚点和生成能力的构件。
- `method`：排列、连接、对齐、路径采样和空间分析等通用方法。
- `composition` 是由多个构件组成且保持结构可编辑的物体或边界明确的系统，网站称为「完整模型」。

先建立可独立复用的构件和单体模型，再用案例验证组合。例如无人机作为一个条目检索和建模，外墙与测区由巡检案例组合。

条目清单位于 `registry/**/manifest.json`，生成索引为 `registry/registry.json`。CLI、编辑器和模型库网站都使用这份索引。

## 贡献约束

1. 条目必须有稳定 ID、语义化版本和明确许可证。
2. 参数必须描述类型、单位、默认值或边界；构件应尽可能参数化。
3. 可连接构件应公开稳定锚点；方法应声明输入与能力。
4. 完整模型用 `dependencies` 记录来源和依赖版本，使用可独立构建的 CompositionSpec 表达自身结构。货物、作业对象和环境由场景案例组合。
5. 新条目必须通过 `npm run registry:check` 和项目测试。
6. 外部模型格式可以作为可选表现资源，但不能替代数字结构与语义定义。

## 当前阶段

当前提供注册表协议、生成索引、CLI 检索和检查、测试及静态 Web 预览。模型的语义、参数、锚点和检查方法应一起维护。

Agent 通过 CLI 检索模型，浏览器可旋转缩放查看模型、复核和复制 CompositionSpec，并把完整模型带入编辑器微调。首批迁移内容包括独立基础双向钢筋系统和水电多路径管线，保留了可参数化几何、空间关系与语义。

教学课件模型的类型覆盖、已迁移条目和后续候选记录在 `courseware-model-migration-inventory.md`，用于避免只积累同一种模型。
