# 开源数字模型库实施方案

## 定位

AgentSceneBuilder 的模型库是面向人和 Agent 的开放数字建模能力仓库，不以收集 GLB、FBX 等成品网格为主要目标。核心积累对象是参数化构件、空间建模方法和可复用组合。

网站是注册表的公开浏览与实验入口；Git 仓库、开放协议和测试才是内容平台本体。短期不建设账号、评论、交易或其他社区运营功能。

## 内容分层

- `component`：具备参数、语义、锚点和生成能力的构件。
- `method`：排列、连接、对齐、路径采样和空间分析等通用方法。
- `composition`：由多个构件组成且保持结构可编辑的完整物体或完整系统；网站称为“完整模型”。它不是教学场景或多个无关对象的陈列。

条目清单位于 `registry/**/manifest.json`，生成索引为 `registry/registry.json`。编辑器和模型库网站消费同一索引。

## 贡献约束

1. 条目必须有稳定 ID、语义化版本和明确许可证。
2. 参数必须描述类型、单位、默认值或边界；构件应尽可能参数化。
3. 可连接构件应公开稳定锚点；方法应声明输入与能力。
4. 完整模型只声明依赖，不复制依赖条目的实现；货物、作业对象和环境不计入模型自身。
5. 新条目必须通过 `npm run registry:check` 和项目测试。
6. 外部模型格式可以作为可选表现资源，但不能替代数字结构与语义定义。

## 当前阶段

第一阶段已建立协议、目录、索引生成器、测试、编辑器入口和静态浏览网站。下一阶段应完善贡献模板、参数交互预览、自动截图和 CI，而不是先扩大条目数量。

网站当前承担面向人的主要入口：可旋转缩放查看模型、检查和复制 CompositionSpec，并把完整数字模型带入编辑器继续修改。首批迁移内容包括旧教学课件中的独立基础双向钢筋系统和水电多路径管线；迁移只保留可参数化几何、空间关系与语义，不复制课件界面和演示流程。

教学课件模型的类型覆盖、已迁移条目和后续候选记录在 `courseware-model-migration-inventory.md`，用于避免只积累同一种模型。
